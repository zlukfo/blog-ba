# Сравнение бинарных и тернарных типов фактов: анализ, преимущества, недостатки и рекомендации

  Данный документ представляет собой глубокий теоретический и практический анализ двух фундаментальных категорий фактов в методологии Объектно-ролевого моделирования (ORM) — бинарных (двухролевых) и тернарных (трёхролевых) типов фактов. Анализ основан на фундаментальной книге Терри Халпина и Тони Моргана *«Информационное моделирование и реляционные базы данных» (Information Modeling and Relational Databases, 3rd Edition)*, в первую очередь на Главах 3, 4 и 14.

Выбор между бинарным и тернарным представлением предметной области — один из ключевых моментов в Процедуре проектирования концептуальной схемы (CSDP). Ошибка на этом этапе приводит либо к потере информации (ловушка соединения), либо к семантической избыточности (неэлементарный тип факта). Понимание формальных критериев разделимости и практических компромиссов необходимо каждому системному аналитику и архитектору данных.

## 1. Теоретические основы: арность фактов
### 1.1 Определение арности

**Арность** (arity) предиката — это количество ролей (объектных «дырок») в нём (Глава 3, стр. 67–68 / PDF 91–92).


``` +-----------------------------------------------------------------------+

|  КЛАССИФИКАЦИЯ ФАКТОВ ПО АРНОСТИ (Глава 3, стр. 67, 107 / PDF 91, 131)|

+-----------------------------------------------------------------------+

|  ТИП ФАКТА     | КОЛ-ВО РОЛЕЙ | ПРИМЕР ПРЕДИКАТА                      |

+----------------+--------------+----------------------------------------+

|  Унарный       |      1       | «… курит»                              |

|  Бинарный      |      2       | «… спроектировал …»                   |

|  Тернарный     |      3       | «… забил … за …»                     |

|  Кватернарный  |      4       | «… судил … иметь … в …»               |

|  n-арный       |      n       | Обобщение для произвольной арности     |

+-----------------------------------------------------------------------+

```

В ORM n-арный предикат отображается как именованная последовательность n ролевых блоков (role boxes), каждый из которых соединён с типом объекта, чьи экземпляры играют эту роль (стр. 68 / PDF 92). Для тернарных и более длинных предикатов чтение включает многоточия «…» в качестве заполнителей (стр. 89 / PDF 113).
### 1.2 Уникальные порядки чтения

n-арный предикат имеет **n! (факториал n)** возможных порядков чтения (стр. 91 / PDF 115):
- **Бинарный (2! = 2):** Прямое и обратное чтение, например «… спроектировал …» и «… был разработан …».
- **Тернарный (3! = 6):** Шесть возможных порядков, например «Политик посетил Страну в Году», «Страна была посещена Политиком в Году», «Год включал визит Политика в Страну» и т.д. (стр. 91 / PDF 115).
- **Кватернарный (4! = 24):** 24 порядка — для практики обычно достаточно одного основного чтения.
На практике для тернарных предикатов отображается только одно чтение (стр. 91). Однако для возможности навигации из любой роли может потребоваться чтение, начинающееся с каждой роли.

## 2. Бинарные типы фактов
### 2.1. Четыре фундаментальных шаблона (Глава 4, стр. 116 / PDF 140)

Бинарные типы фактов имеют ровно **четыре возможные конфигурации** ограничений уникальности (UC):

  

```+-----------------------------------------------------------------------+

|     ЧЕТЫРЕ ШАБЛОНА УНИКАЛЬНОСТИ БИНАРНЫХ ФАКТОВ (Глава 4, стр. 116)   |

+-----------------------------------------------------------------------+

|  ШАБЛОН  | UC на ролях  | ЗНАЧЕНИЕ                  | ПРИМЕР           |

+----------+--------------+---------------------------+------------------+

|  n:1     | Только роль 1| Многие к одному           | Политик родился  |

|          |              |                           | в Стране          |

|  1:n     | Только роль 2| Один ко многим            | Страна является  |

|          |              |                           | родиной Политика  |

|  1:1     | Роли 1 и 2   | Один к одному             | Президент         |

|          | (раздельные) |                           | возглавляет Страну|

|  m:n     | Обе роли     | Многие ко многим:        | Студент изучает   |

|          | (единая      | ключ — вся пара           | Предмет           |

|          |  полоса)     |                           |                   |

+-----------------------------------------------------------------------+

```

Бинарные предикаты обладают **наибольшей ясностью и предсказуемостью** среди всех типов фактов. Их четыре шаблона охватывают все логические возможности и легко проверяются на смысловую корректность методом «трёх строк» (контрпримеры).
### 2.2. Вербализация бинарных фактов

Для бинарных предикатов используется **инфиксная запись** — чтение предиката располагается между двумя объектными термами или с двух сторон от них (стр. 67 / PDF 91):
```

«Человек с фамилией "Вирт" спроектировал язык под названием "Паскаль"»

```

Бинарные предикаты поддерживают **обратное чтение**, отделяемое косой чертой «/» (стр. 69 / PDF 93):
```

«Человек с фамилией "Вирт" спроектировал / был разработан языком под названием "Паскаль"»

```
### 2.3. Функциональные зависимости

Бинарные факты тесно связаны с **функциональными зависимостями (FD)** теории нормализации (стр. 141 / PDF 165). Если X и Y — столбцы, то X! Y означает, что X функционально определяет Y. UC на первой роли в бинарном предикате эквивалентен FD «левая роль → правая роль».

## 3. Тернарные типы фактов

### 3.1. Восемь разрешённых шаблонов UC (Глава 4, стр. 126-127 / PDF 150-151)
Для тернарных фактов существует **8 разрешённых комбинаций** UC (4 базовых + 4 комбинированных), при том что **ни один элементарный тернарный факт не может иметь простой (одноролевой) UC** (стр. 126 / PDF 150):
```+-----------------------------------------------------------------------+

|  РАЗРЕШЁННЫЕ ШАБЛОНЫ UC ДЛЯ ТЕРНАРНЫХ ФАКТОВ (Глава 4, стр. 126-127) |

+-----------------------------------------------------------------------+

|  БАЗОВЫЕ (4 шт.):                     КОМБИНИРОВАННЫЕ (4 шт.):         |

|  +---+---+---+  +---+---+---+        +---+---+---+  +---+---+---+     |

|  | A | B | C |  | A | B | C |        | A | B | C |  | A | B | C |     |

|  +==-+---+---|  +---+==-+---|        +==-+==-+---|  +==-+---+==-|     |

|  |_UC на AB_|  |_UC на BC_|          |UC на AB+AC|  |UC на AB+BC|     |

|                                                                        |

|  +---+---+---+  +---+---+---+        +---+---+---+  +---+---+---+     |

|  | A | B | C |  | A | B | C |        | A | B | C |  | A | B | C |     |

|  +---+---+-==-|  +==-+==-+==-|        +==-+--+-==-|  +==-+==-+==-|     |

|  |_UC на AC_|  |UC на все три|       |UC на AC+BC|  |UC на все пары|   |

+-----------------------------------------------------------------------+

```

**Недопустимые шаблоны (стр. 127 / PDF 151):**
- Простой UC на одной роли — факт заведомо неэлементарен.
- Трёхролевой UC в присутствии двухролевого — подразумевается, избыточен.
### 3.2. Правило n-1 (Глава 4, стр. 140-141 / PDF 164-165)

Фундаментальное правило проверки элементарности тернарных и более длинных предикатов:

> *«Каждый n-арный тип факта имеет длину ключа не менее n-1. Если это правило нарушается, тип факта не элементарен и, следовательно, должен быть разделён»* (стр. 140 / PDF 164).

```+-----------------------------------------------------------------------+

|  ПРОВЕРКА ДЛИНЫ КЛЮЧА ДЛЯ ТЕРНАРНЫХ ФАКТОВ (Таблица 4.6, стр. 140)   |

+-----------------------------------------------------------------------+

|  АРНОСТЬ  | МИНИМАЛЬНАЯ ДЛИНА КЛЮЧА  | НЕДОПУСТИМЫЕ ДЛИНЫ              |

+-----------+--------------------------+----------------------------------+

|  3        |          2               |  1                               |

|  4        |          3               |  1, 2                            |

|  5        |          4               |  1, 2, 3                         |

|  n        |         n-1              |  1, 2, …, n-2                    |

+-----------------------------------------------------------------------+

```

**Математическое обоснование (стр. 140-141):** Если тип факта является элементарным, все его ключи должны быть одинаковой длины. Либо есть ровно один ключ, охватывающий весь тип факта, либо есть один или несколько ключей, каждый на одну роль короче типа факта. Если две или более ролей не являются частью ключа — тип факта составной и подлежит разделению.
### 3.3. Истинный тернарный факт против ложного

#### Случай 1: Истинный тернарный факт (неразделим)

**Пример (стр. 89 / PDF 113):** «Студент 1001 по курсу CS100 получил оценку 4».

```

  Тернарный UC: пара (Студент, Курс) уникальна.
  Каждый студент может получить оценки по многим курсам.
  Каждый курс может иметь оценки многих студентов.
  Одна и та же пара (Студент, Курс) может иметь не более одной оценки.
  Попытка разделения: "Студент набрал Рейтинг" И "Студент изучил Курс"
  → ПРОВАЛ: появляются фиктивные строки (join trap)
  → Факт элементарен, тернарный тип сохраняется.

```
**Детальный анализ ловушки соединения (стр. 153-154 / PDF 177-178):**
Выполним проекцию тернарного факта T(Человек, Оценка, Предмет) на две бинарных:

```

  T2 = T[Человек, Оценка]       ("Человек набрал Оценку")
  T3 = T[Человек, Предмет]      ("Человек изучил Предмет")
  Естественное соединение T2 ⋈ T3 (по Человеку):
  Адамс | 7 | CS112    <- была в оригинале
  Адамс | 7 | CS110    <- НОВАЯ строка! (фиктивная)
  Адамс | 7 | PD102    <- НОВАЯ строка! (фиктивная)
  Адамс | 6 | CS112    <- НОВАЯ строка! (фиктивная)
  ...

```

Появились строки, которых не было в исходной таблице. Информация о том, какой рейтинг по какому предмету получен, **безвозвратно потеряна**. Тип факта не может быть разделён таким образом (стр. 155 / PDF 179).
#### Случай 2: Ложный тернарный факт (разделим)

**Пример (стр. 69 / PDF 93, Таблица 3.3):** «Человек с фамилией "Вирт" разработал язык "Паскаль" в 1970 году».

```
  UC: простая UC на роли «Язык» (каждый язык разработан не более чем за один год).
  Длина ключа = 1 < n-1 = 2.
  Правило n-1 нарушено → факт неэлементарен!
  Разделение:
  «Человек с фамилией "Вирт" разработал язык "Паскаль"»        [бинарный]
  «Язык "Паскаль" был разработан в 1970 году»                   [бинарный]
  Соединение этих двух бинарных фактов полностью восстанавливает
  исходный тернарный без потери информации → Lossless-join декомпозиция.

```
**Второй пример (стр. 141, Таблица 4.7 / PDF 165):** «Страна Австралия имеет население 26 477 504 и площадь 7 686 850 кв. км».

```
  UC: простая UC на роли «Страна».
  Длина ключа = 1 < 2 → неэлементарен!
  Разделение:
  [Страна]--имеет--[Население]  и  [Страна]--имеет--[Площадь]
```

## 4. Подробное сравнение бинарных и тернарных фактов

### 4.1. Матрица сравнения
```+-----------------------------------------------------------------------+
|   СРАВНИТЕЛЬНАЯ МАТРИЦА: БИНАРНЫЕ vs ТЕРНАРНЫЕ ФАКТЫ                  |
+-----------------------------------------------------------------------+
|  КРИТЕРИЙ              | БИНАРНЫЕ (2 роли)    | ТЕРНАРНЫЕ (3 роли)     |
+------------------------+----------------------+------------------------+
|  Количество UC-шаблонов| 4 (n:1, 1:n, 1:1,   | 8 (4 базовых +         |
|                        | m:n)                 | 4 комбинированных)     |
|  Минимальная длина     | Не применимо         | 2 (правило n-1)        |
|  ключа                 |                      |                        |
|  Возможность простого  | Да (n:1, 1:1)        | НЕТ (неэлементарен!)   |
|  UC (1 роль)           |                      |                        |
|  Обратное чтение       | Да (через «/»)       | Теоретически 6         |

|                        |                      | практике — 1            |

|                        |                      | расщеплении             |
|  Частота в реальных    | 80-90%               | 10-20%                  |
|  проектах (оценка)     |                      |                        |
|  Сложность проверки    | Низкая               | Высокая (проверять      |

|  концептуальной        | (если роль необяз.)  | (элементарные факты     |

+-----------------------------------------------------------------------+
```
### 4.2. Преимущества бинарных фактов
1. **Простота и ясность:** Всего 4 шаблона UC, каждый интуитивно понятен.
2. **Лёгкость верификации:** Бинарные предикаты проверяются методом «трёх строк» с экспертами (стр. 113-114 / PDF 137-138). Эксперту показывают три строки таблицы с предполагаемыми дубликатами и спрашивают: «Может ли такая ситуация быть?»
3. **Полнота формальной теории:** Для бинарных предикатов определены 16 комбинаций обязательности и уникальности (стр. 104 / PDF 128), которые полностью охватывают все возможные бизнес-правила.
4. **Прямое отображение в реляционную модель:** Бинарные предикаты n:1, 1:1 и m:n отображаются в таблицы без дополнительных преобразований (Rmap, Глава 11).
5. **Гибкость объективации:** Объективация бинарных предикатов (m:n) — стандартный приём для присоединения дополнительных атрибутов к отношению (стр. 128 / PDF 152).
6. **Простота поддержки обратного чтения:** Косая черта «/» позволяет естественно указать оба направления чтения (стр. 69 / PDF 93).
7. **Стабильность при изменениях:** Добавление новой сущности, связанной с одной из сторон, редко требует изменения структуры бинарного предиката.
### 4.3. Недостатки бинарных фактов
1. **Ограниченная выразительность:** Не все трёхсторонние отношения могут быть адекватно выражены двумя бинарными предикатами. Попытка расщепить истинный тернарный факт на два бинарных приводит к ловушке соединения (join trap) и потере информации (стр. 154-155 / PDF 178-179).
2. **Эффект «размножения» таблиц:** В сильно связанных предметных областях каждое трёхстороннее отношение может потребовать введения коррелирующей сущности (объективации), что усложняет схему.
3. **Менее естественная вербализация для трёхсторонних фактов:** Трёхстороннее отношение «Студент по Предмету получил Оценку» при расщеплении на два бинарных теряет связь между оценкой и предметом.
### 4.4. Преимущества тернарных фактов
1. **Естественное представление трёхсторонних отношений:** Тернарный факт прямо и компактно выражает семантически неразрывные связи между тремя объектами (стр. 89 / PDF 113).
2. **Избежание избыточности:** В истинном тернарном факте каждая строка таблицы фактов уникальна; избыточность не возникает (стр. 126 / PDF 150).
3. **Компактность схемы:** Один тернарный предикат заменяет как минимум два бинарных с коррелирующей сущностью, что сокращает количество типов фактов на диаграмме.
4. **Эффективность при больших диапазонах значений:** Как показано в Главе 14 (стр. 726 / PDF 80), при большом количестве лет (например, 1984-2023) бинаризация тернарного факта о плате за обучение по годам порождает 50+ бинарных предикатов, что загромождает схему и неудобно для просмотра. Тернарная форма компактне

```

  Бинарный подход (громоздкий):        Тернарный подход (компактный):

  [Degree]--fee2021--[USD]             [Degree]...fee in...[Year]--[USD]

  [Degree]--fee2022--[USD]                  |                  |

  [Degree]--fee2023--[USD]             (UC на Degree+Year)

  ... (50+ ролей!)                         |                  |

```

5. **Естественная поддержка m:m:m (многие-ко-многим-ко-многим):** Когда политик может посетить много стран за много лет, тернарный предикат с охватывающим UC на все три роли является единственным адекватным решением (стр. 126-127 / PDF 150-151, РИС. 4.25).
### 4.5. Недостатки тернарных фактов
1. **Сложность проверки элементарности:** Требуется систематическая проверка четырёх возможных способов расщепления (AB, AC; AB, BC; AC, BC; и трёхстороннее — AB, AC, BC). Для каждого способа необходимо проверить, не порождает ли соединение проекций фиктивные строки (стр. 155 / PDF 179).
2. **Невозможность простого UC:** Тернарный факт с UC на одной роли заведомо неэлементарен и должен быть разделён (стр. 127 / PDF 151). Это означает, что все три роли всегда должны быть как-то связаны ограничениями.
3. **Шесть порядков чтения:** Хотя на практике используется одно чтение, возможность навигации из любой роли требует указания нескольких чтений, что усложняет спецификацию (стр. 91 / PDF 115).
4. **Сложность отображения в ER:** Нотация Баркера не поддерживает тернарные ассоциации (Глава 8, стр. 312 / PDF 102). Требуется бинаризация через корреляцию (Шаг 1.2 ERmap, стр. 338 / PDF 128).
5. **Сложность для экспертов:** Эксперты предметной области легче понимают и проверяют бинарные предикаты; тернарные требуют более высокой абстракции.
6. **Проблема семантической 4НФ:** При неверном истолковании отношения (например, независимые бинарные связи, ошибочно объединённые в тернарный факт) возникает избыточность, аналогичная нарушениям 4НФ (Глава 14, стр. 732-733 / PDF 86-87).

## 7. Практические рекомендации и эвристики (Tips & Best Practices)

### 7.1. Эвристика вербализации (телефонная эвристика)

При вербализации факта представьте, что вы диктуете информацию по телефону (стр. 68 / PDF 92). Если в предложении есть слово «и», соединяющее два независимых утверждения об одном объекте — почти наверняка факт составной и должен быть разделён на бинарные.

*Плохо:* «Страна Австралия имеет население 26 млн и площадь 7,6 млн кв. км».
*Хорошо:* «Страна Австралия имеет население 26 млн» И «Страна Австралия имеет площадь 7,6 млн кв. км».
### 7.2. Эвристика телефонного номера
При сомнениях спросите эксперта: *«Может ли одна и та же пара объектов A и B иметь более одного значения C?»*
- Если **НЕТ** — тернарный факт почти наверняка разделим на бинарные.
- Если **ДА** — тернарный факт, скорее всего, элементарен.

**Пример:** «Может ли один и тот же студент по одному и тому же курсу получить более одной оценки?»
→ НЕТ → пара (Студент, Курс) является ключом → тернарный, но это нормально (двухролевой UC допустим для тернарного).
### 7.3. Всегда применяйте правило n-1
Для каждого тернарного предиката проверьте длину самого короткого ключа. Если ключ покрывает только одну роль — **немедленно расщепляйте** без дальнейшего анализа (стр. 140 / PDF 164). Это достаточное условие неэлементарности.

### 7.4. Метод контрпримеров (три строки)
Для проверки, является ли тернарный факт истинным, создайте тестовую таблицу с тремя строками и покажите эксперту. Пример для факта «Студент по Предмету получил Оценку»:

```

  Студент | Предмет | Оценка

  Адамс   | CS112   | 7

  Адамс   | CS110   | 6

  Адамс   | CS112   | 5    ← может ли такое быть?

```

Если эксперт отвечает: «Нет, у студента не может быть двух оценок по одному предмету» — подтверждён UC на паре (Студент, Предмет). Это не делает факт разделимым, но определяет минимальный ключ.
### 7.5. Тест проекционного соединения — только при неясности

Хотя тест проекционного соединения (стр. 155 / PDF 179) является формально корректным методом проверки разделимости, на практике он редко требуется (стр. 155, 180):

> *«Несмотря на то, что тест проекционного соединения полезен для понимания разделимости, он малопрактичен для определения делимости. Проблема в том, что это работает только в том случае, если популяция является значительной. Но знание того, что популяция значительна, означает, что мы знаем все ограничения»*.

На практике достаточно:
1. Применить правило n-1 (отсекает ложные тернарные).
2. Применить эвристику вербализации (отсекает составные).
3. Обратиться к эксперту для подтверждения оставшихся.
### 7.6. Учёт стабильности ограничения значения (Глава 14, стр. 726)

При выборе между тернарным и бинарным (с расщеплением по годам/категориям) учитывайте:
- **Малое стабильное значение (≤5):** Бинарный подход (отдельные роли) — проще для запросов, сравнения значений внутри одной строки.
- **Большое или нестабильное значение (>5):** Тернарный подход — компактнее, легче добавлять новые значения.
```

  Стабильное (пол, {M, F}):     Нестабильное (годы, 1984-2023):

  ─────────────────────────      ─────────────────────────────

  [Сотрудник]--пол--[Код]        [Степень]...плата в...[Год]

         |                             |              |

     {'M','F'}                    UC: (Степень, Год)

  Если бы мы расщепили тернарный платы за обучение на

  50 бинарных (fee1984...fee2023), схема стала бы нечитаемой.

```
### 7.7. Избегайте тернарных фактов при отображении в ER

Если целевая платформа — нотация Баркера ER (Глава 8, стр. 312 / PDF 102), тернарные ассоциации не поддерживаются. Необходима бинаризация через корреляцию (Шаг 1.2 ERmap, стр. 338 / PDF 128). Это добавляет коррелирующий тип сущности. Если ER-отображение обязательно для проекта, рассмотрите возможность изначального использования объективированной бинарной ассоциации.
### 7.8. Объективация как компромисс (Глава 3, стр. 90 / PDF 114; Глава 10, стр. 419 / PDF 73)

  

Вместо тернарного факта можно использовать объективированную бинарную ассоциацию (например, «Зачисление» как объективация пары «Студент-Курс»). Это даёт:

  

- **Преимущество:** Возможность присоединять дополнительные факты к объективированной ассоциации (дата зачисления, статус).

- **Недостаток:** Требуется дополнительный тип сущности; объективация должна иметь охватывающее UC, иначе возможна неатомарность (стр. 419 / PDF 73).

  

```

  Тернарный (плоский):             Объективированный (вложенный):

  [Студент]                         [Студент]

       |--зачислен на--[Курс]            |--зачислен в--[Зачисление]

       |--получил------[Оценка]                     |--привёл к--[Оценка]

       |--в дату-------[Дата]                      |--произошёл в--[Дата]

  Тернарный + ещё один тернарный:   Объективация + два бинарных:

  2 тернарных предиката             1 объективация + 2 бинарных

  (сложнее для отображения)         (проще; гибче)

```

  

### 7.9. Четыре способа расщепления тернарного ABC (стр. 155 / PDF 179)

  

Для тернарного предиката с тремя ролями A, B, C существуют ровно 4 возможных способа разделения на бинарные:

  

1. **AB, AC** — расщепление по общему объекту A.

2. **AB, BC** — расщепление по общему объекту B.

3. **AC, BC** — расщепление по общему объекту C.

4. **AB, AC, BC** — трёхстороннее расщепление (треугольное).

  

Если ни один из способов не даёт lossless-join декомпозиции, факт является истинно тернарным и разделению не подлежит.

  

### 7.10. Принцип «не множьте тернарные без необходимости»

  

Если отношение между тремя объектами может быть адекватно выражено как два независимых бинарных факта без потери информации — **используйте два бинарных**. Тернарные факты должны применяться только тогда, когда это **семантически необходимо**.

  

```+-----------------------------------------------------------------------+

|  ПРИЗНАКИ, УКАЗЫВАЮЩИЕ НА НЕОБХОДИМОСТЬ ТЕРНАРНОГО ФАКТА              |

+-----------------------------------------------------------------------+

|  1. У всех трёх ролей — отношение «многие» (m:m:m).                    |

|  2. Существует UC на всех трёх ролях (охватывающий) или на двух.       |

|  3. Попытка разделения порождает join trap (фиктивные строки).         |

|  4. Вербализация не содержит «и» между независимыми утверждениями.     |

|  5. Количество возможных значений для одного измерения >5              |

|     (например, годы для платы за обучение).                            |

|  6. Эксперт подтверждает неразрывность трёхсторонней связи.            |

+-----------------------------------------------------------------------+

```

## 8. Резюме: Чек-лист выбора между бинарным и тернарным фактом

  

* [ ] **Вербализация:**

  * [ ] Факт сформулирован на естественном языке и проверен на наличие «и» между независимыми утверждениями

  * [ ] Телефонная эвристика пройдена (нет потери информации при разделении)

* [ ] **Проверка по правилу n-1:**

  * [ ] Определена длина самого короткого ключа тернарного предиката

  * [ ] Если длина ключа = 1 (простой UC) → факт НЕЭЛЕМЕНТАРЕН → расщепить на бинарные

  * [ ] Если длина ключа ≥ 2 → перейти к следующей проверке

* [ ] **Проверка четырёх способов расщепления:**

  * [ ] Проверен способ AB, AC (расщепление по A)

  * [ ] Проверен способ AB, BC (расщепление по B)

  * [ ] Проверен способ AC, BC (расщепление по C)
